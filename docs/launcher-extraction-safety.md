# 单文件解压安全边界与验收

本次只修改 C# 解压器，不改系统安全设置。Linux 云端不能编译或执行
.NET Framework / Windows exe，下面的 Windows 项目仍是发布前验收门槛。

## 实现

- 随机 staging 使用 Win32 CreateDirectoryW 独占创建；已有目录不能被
  Directory.CreateDirectory 的幂等行为错误认领。
- 在写 claim 前检查目录链 reparse point；解压的子目录也独占创建并登记，
  文件全部 CreateNew，已有文件、未登记目录、重复文件均拒绝覆盖。
- 发布前再次检查目录链和条目归属；多出的外来条目会使发布失败。
- 临时 ZIP 在同一个 CreateNew、DeleteOnClose 句柄中复制和解压；
  不按路径重新打开或事后删除，复制异常也由句柄关闭处理。
- 解压失败保留 staging 供诊断，不递归删除它或其中可能新增的外来文件。
  原程序目录、旧版本和数据从不删除。确认诊断目录无数据后才能人工清理。
- 子进程非零退出时交互控制台等待按键，避免双击窗口一闪而过；输入
  重定向或非交互环境直接返回错误码。
- 目录名仍采用短指纹以减轻 MAX_PATH 压力，完整指纹保存在标记中；
  短指纹碰撞拒绝覆盖，不将其视为同一安装。

## 证据等级

`node --test tests/packaging/csharp-extraction-safety.test.mjs`
提供 C# 源码约束检查和 Linux 合成文件系统**模型**失败矩阵：
既有 candidate/claim、payload 同名外来文件、claim 后新增外来条目、
符号链接模型、目标冲突及复制中断后的保留策略。
这些测试**不等于 C# 编译、Win32 调用或 Windows junction 验证**。

Windows 隔离环境还须实际验证：
1. 编译 exe，正常首次解压和同版本复用；
2. claim 前替换为 junction 时拒绝，junction 目标未写入 claim；
3. claim 后加入外来文件/目录、同名目标文件时拒绝，外来内容不删除；
4. ZIP 复制失败、损坏 ZIP、sentinel 缺失、磁盘不足时临时句柄释放，
   旧版本不变，staging 保留；
5. 目标版本冲突、并发启动、长路径、非零 Node 退出与输入重定向；
6. 完整迁移交互与账号、任务、附件、Key 保留。

路径检查不是抵御任意同权限恶意进程的沙箱。检查和操作之间仍存在
操作系统级 TOCTOU 窗口；同权限进程替换已登记文件或干预最后发布时，
不能据此宣称对抗性文件系统完全隔离。不要在不可信共享可写目录运行；
如需这一安全等级，应改用句柄相对操作与完整文件身份校验再单独验收。
