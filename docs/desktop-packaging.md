# 桌面版（exe）设计约定

> 状态：**设计已确认，尚未实现**。比赛后再动手。
> 目标：像普通软件一样——一台电脑装一份，装的那台就是服务器，其他人用浏览器连。

## 一、形态选择

| 阶段 | 形态 | 说明 |
|---|---|---|
| 打包顺序 | 先做 L1 文件夹 → 再套壳成 L2 单文件 | L1 方便调试，L2 方便分发 |
| 最终交付 | **L2：一个 exe**（内部按 L1 组织） | 约 110MB；首次运行自解压 |
| 不做 | Electron（L3） | 除非以后要托盘/自动更新 |

## 二、目录约定

```
程序（只读）
  %LOCALAPPDATA%\Programs\ToDoList\
    Todolist.exe

数据（可写，和程序分开放）
  %LOCALAPPDATA%\ToDoList\data\
    app.sqlite        数据库（账号、项目、任务）
    uploads\          附件
    llm\              每个用户自己的模型 Key
    logs\             运行日志

配置
  %APPDATA%\ToDoList\config.json    端口、已授权防火墙、上次打开的网址
```

**铁律：数据目录永远不在程序目录里。** 这样卸载程序不会误删数据，发给别人也不会带走数据。

## 三、首次启动

```
双击 exe
  ↓ 已有实例在跑？→ 激活它的窗口
  ↓ 选端口：4000，被占则 4001…4010，界面上显示实际端口
  ↓ 首次运行：申请管理员权限 → 添加防火墙放行规则（记为已授权）
  ↓ 数据库为空？
      是 → 「欢迎使用 · 创建管理员」（首启向导，已实现）
      否 → 登录页
  ↓
窗口/控制台显示：
    同一 WiFi 下访问  http://192.168.x.x:4000
    [ 二维码 ]
    首次使用请在自己浏览器里完成初始化
```

**其他人**：不装任何东西，浏览器输入网址或扫码即可；注册需要管理员发的邀请码。

## 四、卸载行为（已确认）

| 操作 | 账号 | 项目/任务 | 模型 Key |
|---|---|---|---|
| 卸载（默认，不勾删除数据） | ✅ 保留 | ✅ 保留 | ✅ 保留 |
| 卸载（勾选「同时删除所有数据」） | ❌ | ❌ | ❌ |
| 重装（数据还在） | ✅ 直接登录 | ✅ | ✅ |
| 重装（数据已删） | 首启向导重建 | 空 | 重新填 |
| 覆盖升级 | ✅ | ✅ | ✅ |
| 降级 | ⚠️ 不保证（数据库只向前迁移） | ⚠️ | ⚠️ |

**卸载弹窗文案**

> ☐ 同时删除所有数据（账号、项目、模型 Key）
> 如果你用的是公用电脑，建议勾选。删除后无法恢复。

默认**不勾**。

## 五、备份与恢复（必做）

| 功能 | 位置 | 行为 |
|---|---|---|
| 备份 | 设置页 | 把 `app.sqlite` 复制到用户选定位置（默认桌面），命名带日期 |
| 恢复 | 设置页 | 选择备份文件 → 校验 → 停服务 → 替换 → 重启 |
| 打开数据目录 | 设置页 | 直接打开 `%LOCALAPPDATA%\ToDoList\data` |

没有这两个按钮，用户换电脑就等于从零开始。

## 六、打包时要排除的东西

构建脚本必须拒绝以下内容进入安装包：

- `data/`（数据库、附件、模型 Key）
- `.env`（部署密钥）
- 演示账号（由 `seed-demo-v3.ts` 生成的 11 个账号）
- `test-results/`、`dist/legal` 之外的多余缓存

**验证方式**：装到一个干净的用户账户（或虚拟机）里首次启动，确认出现的是首启向导而不是登录页。

## 七、已知限制（要在发布说明里写清）

| 限制 | 说明 |
|---|---|
| 必须同一个 WiFi | 跨网段、AP 隔离、校园网认证都会导致别人连不上 |
| 主机不能休眠 | 合盖/关机 → 所有人断连 |
| 防火墙规则要管理员 | 首次运行弹一次 UAC |
| 未签名 exe | 首次运行有 SmartScreen 提示（"仍要运行"） |
| 单进程 | SQLite 写锁，同一台机器只能跑一个实例 |
| 手机端体验一般 | 页面是桌面优先布局，能看能用，不是原生 App |

## 八、实施顺序（赛后）

1. **L1 便携目录**：`scripts/package-portable.mjs` 复制 dist / dist-server / node_modules / node.exe + 启动脚本（半天）
2. **启动器**：选端口、提权加防火墙、起服务、开浏览器、显示网址+二维码（半天）
3. **L2 单文件壳**：把 L1 目录压成自解压 exe（半天）
4. **设置页补按钮**：备份 / 恢复 / 打开数据目录（半天）
5. **干净环境验证**：新用户账户首次启动 → 首启向导（半天）

## L11 修复实现与升级说明（本次补充）

便携启动器现在只使用持久用户数据目录：Windows 默认
`%LOCALAPPDATA%\ToDoList`，其他平台默认 `$XDG_DATA_HOME/ToDoList`
（未设置时为 `~/.local/share/ToDoList`）。可以用绝对路径
`TODOLIST_DATA_ROOT` 指定独立目录；不允许指定到程序目录内部。
权限错误立即停止，不再回退到程序目录或临时目录另建空库。
数据库、上传、备份、用户模型/ASR 配置均跟随该目录；
启动器配置实际位于同一根目录的 `config.json`，不是旧文档所写的 APPDATA。

单文件启动器按载荷 SHA256 解压到独立版本目录，不再递归删除旧解压目录。
旧版本中的误放数据会保留。版本目录会累计占用磁盘；确认数据迁移和备份前
不要删除旧目录。Windows C# 编译、真实 exe 覆盖升级还需要 Windows 环境验收。

### 从旧的 ToDoList-app\ToDoList-data 迁移

1. 完全退出旧版和新版程序，保留旧目录备份。
2. 设置 `TODOLIST_MIGRATE_FROM` 为旧的 **ToDoList-data 根目录**
   （应包含 config.json 和 data 子目录），设置 `TODOLIST_MIGRATION_OFFLINE=1`。
3. 启动新版。只向空目标复制整份数据，原文件不删除；已有目标数据、
   SQLite WAL/SHM/journal、符号链接或路径重叠会拒绝迁移，不做目录合并。
   失败时先解决原因，不要直接删除数据库 sidecar。
4. 成功后取消这两个迁移环境变量，再正常启动，核对账号、任务、附件和 Key。
   已有目标库需要人工选择/备份，不能用旧库覆盖。
5. 若旧库不在已识别的 fallback 路径，明确提供实际旧根目录，不猜测。

文件级旧 Key 迁移也改为独占创建副本，保留原件且不覆盖当前配置。
损坏的启动器配置会报错，不会重新生成 sessionSecret。
当前实现**不支持任何自动 Key 重置**，也不会读取 RESET_KEYS.txt；
测试需要清空 Key 时应使用隔离测试数据目录和设置页的明确删除操作。
程序包不得包含这些旧副本、Key 或数据库。

本次云端验证：真实 SQLite 的离线迁移、配置/上传/合成 Key 保留、
目标拒绝覆盖、sidecar/链接拒绝、配置损坏不重置均有回归测试。
测试命令：`node --test tests/packaging/data-root.test.mjs` 及
`npx vitest run tests/server/config-root-migration.test.ts`。

旧库检测也覆盖历史 `%TEMP%\ToDoList`、`%TEMP%\ToDoList-app\ToDoList-data`
以及 exe 同级的 `ToDoList-app\ToDoList-data`。即使这次权限改善，
程序解压位置切回 LOCALAPPDATA，发现这些旧库时也不会静默创建空库；
仅列出候选并要求明确选择离线迁移。已有目标数据库时仍以目标为准，不自动合并。
